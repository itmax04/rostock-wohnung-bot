# AGENTS.md — инструкции для ИИ-агентов и разработчиков

Сначала прочитай `README.md` (устройство, карта файлов, хранилище). Здесь — правила, которые легко нарушить.

## Контекст в одном абзаце

Cloudflare Worker (JS, ES-модули, без сборки) мониторит аренду квартир в Ростоке для одного человека
на Jobcenter: каждые 10 минут читает 5 источников, отбирает по `Kaltmiete + Nebenkosten ≤ 481,80 €`,
шлёт в приватный Telegram-бот. Состояние — Cloudflare KV (`STATE`). Владелец общается по-русски;
комментарии в коде и тексты бота — на русском, письма арендодателям — на немецком.

## Жёсткие ограничения платформы

1. **10 мс CPU на запуск** (бесплатный тариф). Любой новый разбор измеряй: `npm run tail` → `cpuTime`.
   - Разбор страниц — строковыми операциями (`indexOf`, слайсы, заранее собранные `RegExp`).
   - Проверено: `HTMLRewriter` и чтение тела по кускам в Workers **дороже**, чем `await r.text()`.
   - Тяжёлые источники — в отдельные cron-запуски (см. `CRON_TO_SOURCES`).
2. **Cron-расписаний на аккаунт — 5, заняты все** (3 здесь + 2 в `iphone-alert-bot`). Не добавляй новые в
   `wrangler.toml` — встраивай работу в существующие запуски.
3. **KV: 1000 записей в сутки на аккаунт.** Сейчас ~600–700. Не пиши в KV чаще одного раза за запуск
   на источник; новые частые данные — не в KV.
4. Новые расписания после `deploy` начинают срабатывать через ~5–10 минут.

## Правила владельца (не менять без явной просьбы)

- **Не обходить защиту сайтов** (DataDome, Cloudflare/WAF-блокировки, капчи, прокси, headless-браузеры).
  Сайт отвечает 403 боту → источник не подключаем или помечаем как заблокированный.
- **Не отправлять сообщения арендодателям автоматически.** Бот только готовит текст.
- **Не коммитить секреты:** токен Telegram, `RUN_KEY`, `WEBHOOK_SECRET`, Chat Id, базу Fredy.
  Секреты — только через `npx wrangler secret put …`.
- Письмо арендодателю (`src/letters.js`) — короткое, нейтральное, **без** упоминания беженства, Jobcenter, родственников.
- Отбор — по цене и стоп-словам «не квартира». Районы/комнаты/площадь — только для ⭐-сортировки.

## Как вносить изменения

1. Настройки отбора — **только** в `src/config.js`. Не дублируй числа в других файлах.
2. Новый источник: функция в `src/sources.js` → запись в `SOURCES` (`name`, `fetch`, опционально `enrich`,
   `alertOnZero`) → префикс id в `sourceKeyOf` (`src/store.js`) → место в `CRON_TO_SOURCES` (`src/index.js`).
   Формат объявления: `{ id, source, title, description, kalt, nk?, warm, size, rooms, address, lat, lon, url, image }`.
   `id` — `<префикс>:<id на сайте>`, стабильный между запусками.
3. `src/districts.js` не править руками: `data/rostock-bezirke.geojson` → `npm run districts`.
4. Меняешь кнопки — после публикации можно разослать актуальные квартиры заново: `GET /run?key=…&source=resend`.
5. Меняешь команды Telegram — вызови `GET /setup?key=…` (обновит меню и webhook).

## Проверка (обязательно перед тем, как сказать «готово»)

```bash
for f in src/*.js scripts/*.js; do node --check "$f"; done
npm run check          # живые источники локально, без Telegram/KV
npm run deploy
npm run tail           # дождаться cron-запусков: outcome ok, без exceptions, cpuTime ≈ ≤ 10 мс
```
Ключ `RUN_KEY` для ручных вызовов — в локальном файле `.run_key`.

## Частые ловушки

- `parseNumber` убирает точки (немецкий разделитель тысяч) — не применяй к значениям вида `46.19` (WIRO).
- У Kleinanzeigen классы — Tailwind и меняются; опирайся на `data-adid`, `data-href`, JSON-LD.
- `matches:<src>` — это и «уже присылали», и данные для `/all`; не очищай его без нужды.
- Время в cron — UTC; время для людей — `Europe/Berlin` (см. `berlinHourMinute`).
